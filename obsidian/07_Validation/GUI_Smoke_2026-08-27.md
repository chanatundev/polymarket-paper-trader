# Local trade-history GUI smoke review

## Scope

This is a local implementation and browser review of the Phase 5 GUI. It does
not prove live-provider compatibility, live execution safety, accessibility
conformance, or strategy quality.

## Automated evidence

- `uv run python -m pytest -q` — 56 tests passed, including
  `tests/test_history_gui.py` canonical/legacy list and detail joins, filters,
  pagination, bounds, malformed and missing-store handling, URL-safe IDs,
  provider-call isolation, HTML-safe rendering, SQLite immutability, and
  rejection of `POST`, `PUT`, `PATCH`, and `DELETE` routes.
- `uv run --with ruff ruff check pm_trader tests examples` — passed.
- `git diff --check` and staged-diff checks — passed for the implementation
  commits.

## Browser review

On 2026-08-27, the local server was launched with:

```bash
uv run python -m pm_trader --data-dir .pm-trader gui --port 8765
```

The in-app browser loaded `http://127.0.0.1:8765/` and showed the persistent
`PAPER ONLY · LOCAL READ-ONLY` notice, newest-first stored fills, explicit
unknown market labels where the selected store lacked friendly metadata, and
the local-store status. Selecting a row opened Identity, Order, Fill, Market,
Execution, Accounting, Timestamps, Evidence, Assumptions, and Unknowns
sections. The side filter produced a clear empty state; clearing it restored
the rows. The responsive layout was checked at the browser viewport with no
page-level horizontal overflow, and trade rows remained native keyboard-focusable
buttons with visible focus styling and text status cues.

## Remaining gates

The broader release checklist still keeps bounded current-provider probes,
dataset-sharing review, human paper/live wording review, and full accessibility
review separate from this local smoke result.
